## Disposition after review ae7646fe

All five findings were accepted and fixed within Step 3.

1. **Blocker — shutdown admission barrier:** `spawn`, `send`, and `close` synchronously enter an admission set before their first await. `shutdown()` synchronously closes admission, waits the exact in-flight token set, then snapshots and cleans every owned session. Failed shutdown attempts clear only the retry promise; admission remains permanently closed. Deterministic tests gate both a store read in `send` and `acquireSession` in `spawn`, prove shutdown cannot resolve early, then prove the resulting Pi is cleaned and later work is rejected.
2. **Major — restore inode continuity:** established acquisition retains the verified Pi `path/dev/inode/header` identity in the resident session. It is revalidated immediately before rpcFactory/launch and again after `rpc.start()` before state use, stale-task mutation, or prompt. Crash reconciliation retains the same identity. A synchronous rpcFactory test atomically replaces the JSONL with a different inode but identical valid header/native ID; restore rejects `session_identity_changed`, stops Pi, and sends no prompt.
3. **Major — exact terminal retry:** terminal status/detail/completedAt are retained in `TaskRecord`. A failed publication is retried from that exact known result during cleanup; cleanup no longer synthesizes `host_interrupted` for a known completed/failed/aborted result. Tests assert durable task ID, `completed`, and exact response after a transient write failure.
4. **Major — finalization/cleanup serialization and retry:** settled finalization installs `finalizationPromise` before invoking any awaited result lookup or persistence. Cleanup samples/drains before abort, then drains again after abort/stop, retries known terminal publication, performs its final record mutation from the advanced revision, drains the store, and only then releases. `cleanupPromise` always clears after an attempt; `shutdownPromise` clears after rejection while admission stays closed. A gated settle-during-abort test proves no same-revision race; a two-failure test proves first shutdown retains locks, second shutdown succeeds after persistence recovery, and exact terminal result survives. Genuine unconfirmed process-group exit still retains locks.
5. **Minor — support metadata/diagnostic:** package metadata now has `cpu: ["x64", "arm64"]` in package and lockfile. The exported support-matrix string and ownership load error explicitly state macOS/Linux x64/arm64 with Node `>=22.19 <26`; a deterministic metadata test verifies engines, OS, CPU, exact dependency, and diagnostic matrix.
