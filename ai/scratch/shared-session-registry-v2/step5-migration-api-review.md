## Review

- **Major — Known legacy roots silently remain isolated.** `resolveServerConfiguration()` classifies every explicit `PI_AGENT_MCP_STATE_DIR` as non-canonical without detecting `~/.pi/agent-mcp-claude` or `~/.pi/agent-mcp-codex`; startup then skips migration entirely. Reproduce by leaving `PI_AGENT_MCP_STATE_DIR=$HOME/.pi/agent-mcp-claude` in an old client and starting v2: it serves that directory as an independent v2 registry rather than returning upgrade guidance. This preserves the split lock namespaces v2 is intended to eliminate and can make users believe the upgrade succeeded while Claude and Codex still cannot share sessions. `src/server.ts:44`, `src/server.ts:68`, `README.md:54`
- **Major — Free error records without native identity cannot be closed.** Remote close always enters `#acquireForRemoteClose()`, whose nonrecoverable branch rejects records lacking `piSessionId`. Reproduce with a clean migrated v1 `state:"error"` session having no `sessionFile`/`piSessionId`, restart the server, then call `pi_close`; it returns `session_not_recoverable` rather than durably closing the logical record. This leaves valid migrated error records permanently undeletable through the five-tool API, contrary to the specified free-error close behavior. `src/session/session-manager.ts:344`, `src/session/session-manager.ts:469`
- **Major — One corrupt record prevents the entire server from starting.** `SessionManager.initialize()` eagerly lists and caches every disk record, contrary to D10’s locally-owned-only memory map. Reproduce by placing malformed bytes in any final `sessions/*.json` before starting `dist/src/index.js`; initialization throws before MCP connects, so healthy sessions and all five tools become unavailable. The added corrupt-record test inserts corruption only after runtime startup and therefore misses this production boundary. `src/session/session-manager.ts:137`, `test/server-runtime.integration.test.ts:220`
- **Major — Required two-stdio-server black-box coverage is absent.** The shared-runtime test constructs two `createServerRuntime()` objects inside one Node process; the only stdio E2E starts one server and tests shutdown. Reproduce by inspecting/running the suite: no test launches two `dist/src/index.js` processes against one root and exercises cross-process status/wait/contention/takeover. This leaves the Step 4 validation and BRIEF multi-process criterion unattested at the actual stdio/process boundary. `test/server-runtime.integration.test.ts:160`, `test/stdio-shutdown.e2e.test.ts:51`
- **Minor — Record reads do not enforce documented `0600` mode or ownership.** `readSecureFile()` validates type, symlinks, and inode identity but not mode/UID. Reproduce by creating a valid record, `chmod 0644` on its final JSON, then calling `pi_status`; the record is accepted despite the frozen layout’s `0600` requirement. A private `0700` root mitigates immediate disclosure, but the stated defense-in-depth invariant is absent and untested. `src/store/secure-fs.ts:94`, `src/store/session-store.ts:78`
- **Minor — Semantically corrupt lifecycle combinations pass record validation.** Validation only type-checks `recoverable` and `activeTaskId`; it accepts, for example, a `closed` record with `recoverable:true` and a non-null active task. Reproduce by writing that record under its correct hash: `pi_status(id)` reports a closed session with current work, while `pi_wait` can continue returning the impossible task as pending rather than rejecting the record as corrupt. `src/store/session-store.ts:176`, `src/session/session-manager.ts:898`
- **Minor — MCP errors can expose absolute internal paths.** `toolResult()` passes unmatched errors through `publicErrorMessage()` verbatim. Reproduce by corrupting a final record after startup and invoking `pi_status` through MCP; the returned JSON includes `Invalid session record /absolute/state/root/...`. Ownership/migration prefixes are correctly classified, but corrupt-record and secure-filesystem failures lack equivalent classification/redaction. `src/server.ts:205`, `src/server.ts:250`
- **Minor — Exact tool-schema compatibility is not asserted.** The MCP integration test verifies only the five names, not the JSON input schemas, required fields, defaults, bounds, or optionality. Reproduce by changing a registered field from optional to required while retaining tool names; the list assertion and most happy-path calls still pass. This leaves the frozen “existing input shapes” contract weakly protected. `test/mcp-tools.integration.test.ts:42`, `README.md:72`
- **Minor — Retirement naming drifts from the frozen migration protocol.** The implementation and README use random `sessions.v1.quarantine-<migration-id>-<uuid>.json` paths, whereas the authority specifies `sessions.v1.retired-<content-hash>.json`. Reproduce any successful v1 import and inspect the legacy directory. Data remains preserved and intent records the path, so this is compatibility/operational drift rather than source-atomic data loss. `src/store/v1-migration.ts:184`, `README.md:63`

## Correct

- `resumeIncomplete()` is invoked before live source discovery at `src/server.ts:218`.
- Canonical discovery includes canonical, Claude, Codex, and explicit legacy roots with lexical deduplication.
- Dirty manifests require `PI_AGENT_MCP_IMPORT_DIRTY=1`; active tasks become `host_interrupted`.
- Candidate locks are deduplicated and ordered migration → source → logical → native.
