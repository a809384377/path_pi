## Review

### Blocker
- **Persistence failure prevents process cleanup and can hang stdio shutdown.** `src/session/session-manager.ts:537` awaits the failed terminal save, then `src/session/session-manager.ts:541` throws before reaching RPC cleanup at `src/session/session-manager.ts:555`. The EOF handler only records the rejection at `src/server.ts:124`; it does not force process cleanup or exit. **Reproduction:** use a real fake-Pi process with a store that rejects the terminal-outcome save, emit `agent_settled`, then close MCP stdin. `manager.shutdown()` rejects before `rpc.stop()`, leaving Pi/tool processes resident and the stdio server alive. The existing regression explicitly expects shutdown rejection at `test/session-manager.integration.test.ts:380`, but uses `ControlledRpc` and never verifies process cleanup.

### Major
- **`pi_wait` hides terminal persistence failures as indefinitely pending tasks.** Wait only observes `published` terminal tasks at `src/session/session-manager.ts:220`, while save failure records `persistenceError` without publishing at `src/session/session-manager.ts:462`; timeout therefore continues returning the task in `pending` through `src/session/session-manager.ts:479`. Only a separate `pi_status` exposes the error at `src/session/session-manager.ts:655`. **Reproduction:** the existing test at `test/session-manager.integration.test.ts:371` injects `disk full`; both waits time out at `test/session-manager.integration.test.ts:373` and `test/session-manager.integration.test.ts:374`, despite the task already having a known terminal outcome. An MCP caller using the documented spawn→wait workflow receives no failure diagnostic.
- **Process-tree cleanup is confirmed only for the Pi leader, not all tool descendants.** `src/rpc/pi-rpc-process.ts:261` sends group `SIGTERM`, but returns immediately when the Pi leader exits at `src/rpc/pi-rpc-process.ts:262`; group `SIGKILL` at `src/rpc/pi-rpc-process.ts:263` is then skipped even if a tool child ignored `SIGTERM`. `SessionManager` can consequently mark `cleanShutdown:true` at `src/session/session-manager.ts:286` while that descendant survives. **Reproduction:** replace the fixture tool child with one that ignores `SIGTERM`; let Pi itself exit normally on group TERM, close stdin, and observe the tool PID still alive after the server writes a clean manifest. The E2E fixture’s child at `test/fixtures/fake-pi.mjs:81` is cooperative, so `test/stdio-shutdown.e2e.test.ts:97` does not cover this case.

### Minor
- **The persistence latch introduces an undocumented MCP status state and manifest/runtime divergence.** Runtime exposes `"finalizing"` through `src/session/session-manager.ts:20` and `src/session/session-manager.ts:648`, but the frozen/design and README contract omit it at `README.md:118`. During that state, serialization projects the future state and clears the persisted active task at `src/session/session-manager.ts:668`, while runtime status still reports `finalizing` with the active task. **Reproduction:** gate the terminal save as in `test/session-manager.integration.test.ts:349`, emit `agent_settled`, and call `pi_status` before releasing the save; the caller receives the undocumented state while the save snapshot represents the session as terminal/idle.
- **The stdio E2E has a process-exit race and incomplete failure cleanup.** After only the server/leader exit is awaited, `test/stdio-shutdown.e2e.test.ts:96`–`test/stdio-shutdown.e2e.test.ts:98` perform one-shot PID checks with no bounded polling. A descendant that handles TERM but exits slightly later causes a false failure. The `finally` block at `test/stdio-shutdown.e2e.test.ts:102` kills only the MCP server, so an assertion/setup failure can leave Pi/tool descendants behind. **Reproduction:** make the tool child delay exit by 50 ms after SIGTERM; the server can exit first and the immediate child PID assertion fails even though cleanup completes shortly afterward.
- **Fresh-package behavior is fixed in source but lacks a clean-pack/install/bin regression.** `package.json:17` adds `prepack`, `package.json:6` points the bin at built output, and `package.json:12` includes `LICENSE`; however no test creates a fresh tarball and executes the installed bin. **Reproduction command for the supervisor:** from a clean checkout run `npm ci && npm pack`, inspect the tarball for `dist/src/index.js` and `LICENSE`, install it into a temporary project, then perform MCP initialize/list-tools through the installed `pi-agent-mcp` binary.
